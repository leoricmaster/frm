# 文档梳理清理与主文档精炼设计

- 日期：2026-09-07
- 状态：设计已与发起人逐项确认（清理范围/处置方式/交付方式/读者定位/结构方案）
- 定位：仓库文档从"工具过程产物混杂"重组为"人类阅读、同步与评审"导向

## 1. 背景与目标

仓库文档随三阶段原型验证自然生长，`docs/superpowers/` 下混着已完结的实施计划（约 2600 行任务清单）与正式设计文档；仓库根没有 README，人类进仓库无入口。目标：

1. 清除过程类文档，只留人类要读的主文档；
2. 建立面向评审者的目录结构与入口；
3. 对主文档逐一评审精炼——逻辑结构清晰、内容简洁，适合发起人+团队内部评审。

读者定位：**发起人+团队内部**（懂项目背景）——可砍背景铺垫与重复叙事，保留决策、规则、接口、实测边界。

## 2. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 清理范围 | 6 个实施计划 + 原型测试计划 + 教程设计稿（共 8 文件） |
| 处置方式 | 删除 + 蒸馏：test-plan 中被 ADR/设计/教程引用的验证结论浓缩为一页保留 |
| 精炼交付 | 逐文档评审报告 → 用户逐处确认 → 执行修改（不擅自砍内容） |
| 结构方案 | 方案一"归位重组"：设计迁入 `docs/design/`，新建根 README |
