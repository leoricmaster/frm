# ADR-0002：版本策略——gitlab-ee 免费运行，Premium 痛点再升

- 状态：已接受
- 决策日期：2026-08-31
- 来源：[统一代码管理体系设计 §3.2](../design/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0001（平台选型）

## 背景

GitLab 付费（Premium）版缺失若干功能，需明确用哪个发行版运行、缺失功能如何补、何时升级。

## 决策

1. 安装 `gitlab-ee` 包但**不注入 license**，按免费功能运行；将来购买 license 即升级、无需重装。可询价极狐 GitLab（官方中国发行版）作备选；
2. CE 缺失功能用制度与 CI 替代，**痛点成为真实痛点或集团审计提出要求时再升级**：

| 缺失功能 | CE 下的替代 |
|---|---|
| MR 审批规则（强制 N 人批准、CODEOWNERS） | 保护分支限 MR 合入（系统强制）+ 批准人数制度约定 |
| Push rules（推送拦截密钥） | CI 首条任务跑 gitleaks 密钥扫描 |
| 审计事件流 | 基础日志定期归档 |
| SAML/LDAP 分组同步 | LDAP 认证 CE 即有，分组手动维护 |

## 考量

- CE 为 MIT 协议，**商用免费、自建实例用户数不限、CI 分钟数不限**（"5 用户上限"仅存在于 GitLab.com SaaS 免费版，与本方案无关）；
- 替代方案共同点：系统强制的部分用系统（保护分支），人为约定的部分用宪法仓库 + checklist——不假装有硬约束。

## 否决的备选方案

- 一步到位买 Premium——为尚不存在的痛点付费；
- 纯 CE 包——将来升级要重装，ee 包免费运行两全。

## 后果

- 正面：零 license 成本起步，升级路径无损；
- 代价：审批人数、推送拦截是**制度约束不是系统约束**，依赖 MR 模板 checklist 与 Owner 合码纪律执行。

## 重新打开的条件

- 强制 N 人批准成为真实合规要求（如集团审计、功能安全流程）→ 评估 Premium；
- 需要审计事件流对接安全部门 → 同上。
