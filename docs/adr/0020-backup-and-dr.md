# ADR-0020：备份容灾与恢复演练

- 状态：已接受
- 决策日期：2026-08-31
- 来源：[统一代码管理体系设计 §11](../superpowers/specs/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0011（MinIO 里是不可再生资产）、ADR-0001（体系取代个人电脑成为权威副本）

## 背景

体系取代个人电脑成为代码权威副本后，体系自身的数据丢失就等于原来"电脑坏了代码没了"的风险整体回归——备份是方案成立的底线。其中现场采集数据**不可再生**。

## 决策

1. GitLab 原生全量备份（配置 + 仓库 + 数据库）**每日**，保留异地/离线副本；
2. LDAP、Harbor、MinIO 各自配置快照；
3. **MinIO 数据按资产备份**：数据集、模型权重、现场采集数据不是缓存而是资产——按数据分级确定保留与备份策略，纳入与代码同级容灾；
4. **恢复演练每半年一次**。

## 考量

- **未演练过的备份等于没有备份**——演练不是加分项，是备份定义的一部分；
- 数据分级先行：可再生的（CI 缓存、代理缓存）与不可再生的（现场采集、权重）备份策略不同。

## 否决的备选方案

- 只备份 GitLab 不管 MinIO——数据资产全丢，回到方案要解决的原始问题；
- 备份不演练——恢复时才发现备份损坏/缺组件，等于没备。

## 后果

- 正面：单点丢失风险在体系层面闭环；恢复能力有周期性证据；
- 代价：备份存储与演练是平台维护人的固定职责（计入其工作量，防断档风险）。

## 重新打开的条件

- 数据量级增长使每日全量不可行 → 增量/分层备份策略修订。
