# ADR-0008：DLP 两区模型与构建区豁免

- 状态：已接受
- 决策日期：2026-08-31
- 来源：[统一代码管理体系设计 §5](../design/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0013（出口收敛是交换条件之一）、ADR-0014（驻场终端全量 DLP）、ADR-0011（产物不加密）

## 背景

集团 DLP 为透明加解密类（对 CI/CD 影响最大的形态）。若构建区也装 agent：构建产物被加密、Docker 分层缓存失效、CI 缓存损坏——流水线根本跑不起来；若 git 未授信：仓库文件被二次加密，push 上去的是密文垃圾。与安全部门的谈判必须发生，问题是姿态。

## 决策

**两区模型**——把与安全部门的谈判变成**交换**而非对抗：

| 区域 | DLP Agent | 网络位置 | 放什么 |
|---|---|---|---|
| 办公研发区 | 安装 | 公司办公网 | 工程师笔记本/工作站 |
| 机房构建区 | **豁免** | 隔离网段，仅通内网 | GitLab、Runner、GPU、镜像/制品库 |

1. 向 IT/安全申请三件事：**构建区豁免**（不装或仅审计模式）；**终端进程授信**（git/ssh/IDE 进授信白名单）；**文件类型策略**（源码类加密；.bin/.o/.img 等构建产物不加密——产物要在无数无 agent 设备上运行）；
2. 交换条件：构建区**无外网直连**（拉包走内网代理，见 ADR-0013）+ 机房门禁与运维审计 + GitLab 审计日志归档供调阅 + **驻场终端照常全量装 DLP**（工地丢失硬盘是密文）；
3. 衍生铁律：**对外交付制品必须在构建区构建**，禁止"在我电脑上编译一个先凑合"。

## 考量

- 机制基础：透明加解密只作用于终端磁盘，代码的**加密边界始终在终端**——这是两区模型成立的物理解释，也是谈判的核心论据；
- 授信机制细节需拿到集团 DLP 产品名后核对其官方文档（阶段 0 行动项）。

## 否决的备选方案

- 对抗/绕过——不可行也不可持续；
- 构建区全装 agent——CI 不可用，等于放弃方案 A。

## 后果

- 正面：CI 可用性与终端防泄漏并存；驻场场景（笔记本丢工地）风险闭环；
- 代价：谈判周期不可控（§10 已列风险：阶段 1/2.5 工期从书面结论起算，不提前承诺日期）；产物不加密意味着含源码产物（镜像内 Python 等）以产物身份离开加密边界——行业普遍接受，但谈判时安全部门可能追问，答案是制品库在内网受信区、有权限与审计。

## 降级路径（谈判破裂时，非死局）

- 降级一：构建区装 agent 但策略降为仅审计；
- 降级二：构建任务回退到装 agent 的虚机跑、接受性能损失。

## 重新打开的条件

- 集团 DLP 产品换代或策略变更 → 重核授信与豁免清单；
- 降级一/二被触发 → 本 ADR 的豁免条款失效，记录触发事件。
