# ADR-0001：平台选型——自建 GitLab CE 一体化平台

- 状态：已接受
- 决策日期：2026-08-31（设计评审确认）
- 来源：[统一代码管理体系设计 §3.1](../superpowers/specs/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0002（版本策略）、ADR-0003（仓库结构）、ADR-0009（CI 分层）

## 背景

代码散落个人电脑，两类风险：违反集团防泄漏规定（DLP 压力）、单点丢失（DLP 不覆盖）。团队 50+ 人、多团队，代码栈四类并存（固件/算法/车载/云端+App）。集团是否已有托管平台不明、不知道找谁，推进策略为自下而上带方案推动。

## 决策

自建 **GitLab CE 一体化平台**（方案 A）：代码托管、权限、MR 评审、CI、镜像库、制品库一站覆盖。

## 考量

- 一体化意味着账号、权限、审计天然在一套系统里——拼装方案的三套账本是 50+ 人团队的维护灾难；
- 国内制造业研发中心私有化部署的事实标准，招聘与推广叙事顺；
- 方案必须**自洽可独立落地**，同时预留接入集团设施的平滑迁移接口。

## 否决的备选方案

- **方案 B：Gitea + Jenkins + Harbor 拼装**——组件轻量但权限/账号/审计分散在三套系统；Jenkins 易演化成新的个人黑盒。适合 10 人以下，50+ 人否决；
- **方案 C：接入集团设施**——不作为独立方案，而是 A 的**演进路径**：GitLab 仓库可整体迁移，仓库结构、CI 配置、权限模型全部带走，A 的投入在 C 场景下不作废。

## 后果

- 正面：单一系统承载全部体系，后续 ADR（权限/CI/需求流）都建立在一体化之上；
- 代价：需自运维——备份、升级、平台维护人（设计 §10 已列"平台维护断档"风险）。

## 重新打开的条件

- 集团统一代码托管平台落地且可对接 → 启动方案 C 迁移评估（结构/配置/权限全带走）；
- 团队缩到 10 人以下 → 拼装方案的维护成本劣势消失，可重议。
