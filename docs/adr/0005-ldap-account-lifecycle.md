# ADR-0005：账号体系——LDAP 域账号生命周期

- 状态：已接受（2026-09-07 补精确边界）
- 决策日期：2026-08-31；边界注 2026-09-07
- 来源：[统一代码管理体系设计 §4.3（含边界注）](../design/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0002（分组同步是 Premium 功能）、ADR-0004（权限三级）

## 背景

账号若本地手工建，入离职全靠人记得开/删——必然漏。集团有 LDAP 域账号体系可对接。

## 决策

1. GitLab 对接集团 LDAP 域账号（CE 原生支持登录认证），**禁止本地建账号**；
2. root 本地账号保留为 break-glass 应急通道，是唯一例外，密码受控保管；
3. 配 user_filter 限定可自动建号的范围（不配则全集团域都能登录）。

## 精确边界（CE 开箱能力，2026-09-07 确认）

| 环节 | 自动程度 | 补法 |
|---|---|---|
| 入职自动有账号 | ✅ 域账号首次登录自动建号 | 无需操作 |
| 入职自动有权限 | ⚠️ 手动加组（CE 无分组同步） | Maintainer 操作；或升 Premium |
| 离职：登录失效 | ✅ 域账号禁用后登录/HTTPS 密码认证立即失败 | 依赖 IT 禁用时效 |
| 离职：存量访问（SSH key、令牌、会话） | ❌ 不自动失效 | **定时脚本比对 AD 禁用名单 → 调 API 封禁账号**（阶段 1 实施项） |

## 否决的备选方案

- 本地建号 + 人工离职删号——靠人记得，必漏，正是本决策要消灭的；
- 升级 Premium 用 LDAP group sync 全自动——为零痛点付费，先用手动 + 脚本。

## 后果

- 正面：入离职不依赖任何人记得操作；账号来源唯一（域），审计干净；
- 代价：封禁脚本是要维护的代码；LDAPS（636）+ 服务账号（bind DN）需向集团 IT 申请（干系人清单 §9）。

## 重新打开的条件

- 集团 IdP 变更（换域、加 SAML）→ 重议对接方式；
- 分组手动维护成本被证明过高 → 重议 Premium group sync（ADR-0002 同款条件）。
