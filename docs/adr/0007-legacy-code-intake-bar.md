# ADR-0007：存量代码收编门槛

- 状态：已接受
- 决策日期：2026-08-31
- 来源：[统一代码管理体系设计 §4.4、§8 阶段 2、§10](../design/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0003（收编目标地）、ADR-0001（背景：消灭单点丢失）

## 背景

存量代码散落个人电脑，质量参差，部分说不清用途、没人在用。若原样搬进新体系，只是把混沌换了存放地点。

## 决策

1. 入库门槛：**能编译 + 有 README（用途 / Owner / 依赖）**；
2. **说不清用途的代码不入库**——宁可在迁移中淘汰，不把个人电脑里的混沌原样搬进新体系；
3. 迁移期间**只立规则不追旧账**：历史不追究，从今往后按新规则。

## 考量

- 体系的原始目标是消灭单点丢失与泄漏面——无主代码两者都不解决，反而扩大审计负担；
- "不追旧账"是给抵触情绪的对冲：过去怎么写的不议，只约束入库之后。

## 否决的备选方案

- 全量收编后再清理——无主代码进了库就永远没人清，且 README 永远补不上；
- 先入库存档（archive 分支）——降低门槛的口子一开，"说得清用途"的追问就失效。

## 后果

- 正面：库里每一行代码有主、能编译、可追责；
- 代价：部分代码会在迁移中被淘汰——这是特性不是缺陷，需发起人背书"淘汰是允许的"；
- 里程碑：**个人电脑不再是代码权威副本所在地**（正式宣布）。

## 重新打开的条件

- 收编完成后本 ADR 使命结束，转为对新仓库的常态门槛（建仓三问：哪个域 / Owner 是谁 / 说得清用途吗）。
