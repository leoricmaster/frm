# ADR-0014：驻场离线基线

- 状态：已接受
- 决策日期：2026-08-31
- 来源：[统一代码管理体系设计 §7](../superpowers/specs/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0008（驻场终端全量 DLP）、ADR-0011（签名制品 + manifest）、ADR-0018（现场改动天然有单）

## 背景

驻场网络条件混合：部分现场无网/弱网，部分可 VPN 回公司。流程若赌现场有网，必然在关键时刻失效。

## 决策

**离线为基线、有网为加速**——流程不赌现场有网：

1. **出场前**（公司内）：`git pull` 同步代码 + 从 Release 下载已签名制品，按 `platform/` 出场 checklist 核对（代码、制品、工具链版本、联系人）；
2. **现场三类工作三条通道**：

| 工作内容 | 通道 | 关键规则 |
|---|---|---|
| 调试、刷固件 | 预构建签名制品 + manifest 核对 | **现场永远不编译**；要新版本走通道 2 |
| 改代码 | DLP 笔记本本地 commit → 有网即 push → MR → CI 构建 → 下载刷入 | 改动**必须**以 commit 回中心仓库——防代码重新散落回个人电脑 |
| 取数（日志、传感器数据） | 进 MinIO 投放区（能连则直传，否则回公司上传） | 数据向内流、代码向外只走 git |

3. **应急缝有账可查**：断网+机器急等允许刷本地临时包，但回公司 **24 小时内补齐 MR 和正式构建**，否则按违规处理；
4. VPN 场景体验与公司内一致，但 **VPN 终端上的 DLP 不因 VPN 放松**；现场 U 盘按集团外发策略走审批加密盘。

## 考量

- "临时包是救火用的，不是工作方式"——向团队明确传达；
- 本地验证与正式构建分离：允许笔记本临时编译验证，刷上机器的正式版本必须来自 CI 签名制品（可追溯性不可妥协）。

## 否决的备选方案

- 赌现场有网的在线流程——关键时刻失效，且失效发生在最忙的时候；
- 禁止现场改码（一刀切）——现实需要 bug 修复，堵死只会催生绕过。

## 后果

- 正面：网络条件不影响流程成立；现场版本永远可追溯到 commit；
- 代价：24h 补账依赖自觉 + 例会检查，是全体系最依赖纪律的一环。

## 重新打开的条件

- 现场网络条件普遍改善（VPN 全覆盖）→ 可放宽出场打包，通道规则不变。
