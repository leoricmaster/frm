# ADR-0010：Runner 池标签化与触发分级

- 状态：已接受
- 决策日期：2026-08-31（池表）；触发分级细化 2026-09-07 讨论确认
- 来源：[统一代码管理体系设计 §6.1](../superpowers/specs/2026-08-31-excavator-code-management-design.md)
- 关联：ADR-0009（CI 三层）、ADR-0011（产物去向）

## 背景

四类代码栈的构建需求差异极大（交叉编译/GPU 训练/HIL 台架/容器构建），单一 Runner 池会互相踩踏；GPU 与 HIL 是独占资源。

## 决策

1. **Runner 池标签化**，GitLab 主机只做调度不做重活：

| Runner 池 | 标签 | 硬件 | 跑什么 |
|---|---|---|---|
| `fw-build` | docker, cross-* | 机房虚机 ×2 | 固件交叉编译、静态检查 |
| `algo-gpu` | gpu | GPU 服务器 | 模型训练、仿真回放测试 |
| `veh-build` | docker | 机房虚机 ×1 | 车载 C++/Qt 构建打包 |
| `cloud-deploy` | docker, deploy | 机房虚机 ×1 | 云端构建部署 |
| `hil-rig` | rig | HIL 台架实体机 | **手动触发**的 HIL 测试 |

2. **触发分级**（2026-09-07 细化）：push/MR 跑快门槛（编译+单测+静态检查，目标 <10 分钟）；全量仿真回归、数据集回放评测、HIL、长时测试放 nightly/tag；GPU 全量评测不进 per-push（排队资源）。

## 考量

- 独占资源（GPU、HIL 台架）必须显式排队：HIL 只能手动触发或 nightly 串行，绝不 per-push（两条流水线抢一个台架）；
- 与行业实践一致：成熟机器人团队都收敛到"push 快验 / nightly 全量 / tag 发布"三档。

## 否决的备选方案

- 单一大池——构建互相踩踏、GPU 任务阻塞固件编译；
- 每团队自建自管 runner——回到拼装时代的分散运维。

## 后果

- 正面：资源隔离、故障隔离（一个池挂不影响其他域）；标签即调度语义；
- 代价：池容量规划是平台组的持续工作（fw-build 满载时加虚机，不是改架构）。

## 重新打开的条件

- 某池长期满载或长期闲置 → 调整池表（容量修订，不动架构）；
- 出现新型构建形态（如移动端 CI）→ 新增池，走本 ADR 修订。
